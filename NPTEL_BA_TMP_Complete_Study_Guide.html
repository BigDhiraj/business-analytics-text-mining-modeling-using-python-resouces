2.1 Structured vs unstructured data

Key definition — structured numeric data

“Uniform measurements are taken for all the observations in the sample.” That single sentence is the definition the slides give. More fully, structured data for data mining:

  • Requires data preparation involving data-transformation steps.
  • Data-collection effort may be based on careful prior design for mining.
  • Measurements are well-defined and recorded uniformly for every observation in the sample.
  • Types of variable measurements: continuous (interval, ratio) and categorical (nominal, ordinal).
  • Is finally described in a highly structured tabular / matrix format.

In that table, a row is a complete example of past experience and a column is one measurement taken uniformly for all the rows. Because of this uniformity, “we can operate in a typical mathematical fashion” — which is the whole point.

Key definition — unstructured data

Text is typically described as unstructured data. Its initial presentation is a variant of XML format, and it is then transformed into numerical data leading to the same tabular format used in data mining.

The bridging argument, in the slides' own words: machine-learning algorithms can model prediction problems using either structured numerical measurements or unstructured text, “because text and documents can be transformed into measured values” — where the presence or absence of words on the column side is indicated against documents on the row side. That leads to the common representation used for numeric data.

2.2 Data mining vs text mining Exam alert

Three key differences are listed explicitly:

  1. Evaluation techniques — chronological order of publication, and alternative measures of error.
  2. The data are text and documents — so specialized techniques may be preferred.
  3. Techniques must be modified to work with high-dimensional data — tens of thousands of words and documents.

But the two share a core: “both are about finding valuable patterns in data” and “both are about learning from samples of past experience or examples”.

Related-but-different field

In the related domains of Natural Language Processing and Search Engine Technology, the focus is on linguistic techniques — the essence of language understanding. Text mining is moving closer to the generic machine-learning paradigm: learning from data, whether numerical or text. The main theme in text mining is that it is empirical in nature — mine for recurring word patterns in large text collections or large collections of digital documents.

On the “how is text mining different” question, the slides frame it as “a progress from applying analytics on large data to ‘big data’”, because nowadays most data originate in digital form due to the pervasive use of computers. Four examples of activities now performed electronically: stock trading, writing a book, buying a product online, and digital transactions (many paper-based transactions have been replaced by paperless digital alternatives).

2.3 The binary spreadsheet — the central representation

Key definition — words as attributes, documents as cases

“Words are attributes / predictors and documents are cases / records.” Together they form a sample of data that can feed well-known learning methods.

  • For text, a row represents a document (an example of prior experience).
  • A column represents measurements taken to indicate the presence or absence of a word for all the rows.
  • Cells are filled with 1s & 0s.

The worked example on slide 14 is a binary spreadsheet with four documents and four word-columns:

Why this matters

This is why techniques similar to data mining can be used in text mining, and they have been found to be very successful — without understanding specific properties of text such as the concepts of grammar or the meaning of words.

Key definition — the dictionary

Given a collection of documents, the set of attributes is the total set of ‘unique words’ in the collection, and this is called the dictionary.

For thousands or even millions of documents, the dictionary will converge to a smaller number of words. However, technical documents with alphanumeric terms may lead to very large dictionaries, and the tabular layout “can become too big in size to be practical”.

Key definition — machine learning, as this course defines it

Machine-learning techniques “can be described as statistical techniques without prior knowledge”: they typically don't make any assumption about the data the way statistical techniques do. The illustration given is that multiple linear regression assumes a linear relationship between Y (target) and the Xs (predictors); the deficiency is instead counterbalanced with massive processing of data, finding recurring and predictive patterns in word combinations.

2.4 Sparsity and missing values

  • For a large enough collection of documents, the tabular / matrix layout would be too sparse — any individual document uses only a tiny subset of the potential set of words in the dictionary.
  • Techniques that process text expect the sparse data, and store only positive cell values in their actual implementations. The tabular layout is used mainly for conceptual clarity.
  • All the values in a text-mining spreadsheet are positive — text-mining programs use this characteristic to simplify processing.
  • Missing values are a big problem in data mining. For text, missing values are a non-issue — all cells are completely filled, since we only indicate presence or absence of words.
  • Numerous variations of the simple tabular layout for text have been suggested by researchers.
Exam alert — the two most-likely Module I MCQs

(1) “In text mining, missing values are…” → a non-issue, because every cell is filled with a presence/absence indicator.
(2) “Why can data-mining techniques be applied to text?” → because text can be transformed into a numerical presence/absence matrix, without needing grammar or word meaning.

Predictive text analytics consists of primarily two types of tasks — Prediction and Classification. Two further tasks are required in certain scenarios, as the slides quantify it:

  • Clustering — required when “the labels required for text categorization or document classification are not known already”.

The slides are precise: prediction and classification are the primary tasks; clustering and extraction are secondary / scenario-dependent. An MCQ that says “the four primary tasks of predictive text analytics are…” is testing whether you noticed this.

2.6 Prediction and evaluation

Key definition — the modelling process

The text-mining modelling process is similar to the data-mining modelling process:

• Build models based on prior cases (from the training partition).
• Use the built model to predict the unseen cases (from the test partition).
• Evaluate model success based on its performance on the test partition, which is not part of the model building process.

This mechanism “works well for most of the text-mining scenarios — however, there might be few special scenarios.”

Special scenarioWhat the slides say
Topic assignment
Exam alert		 Assigning topics to news stories, such as financial or sports stories. But news stories might change over time. Therefore, news stories for the test partition should be selected taking into account this sensitivity towards dates of publication — since the model-training process typically won't account for changes over time.
Measurement of error
Exam alert		 Classical measures of accuracy work well if all errors are to be evaluated equally. However, as in the topic-assignment problem, not all errors will be evaluated equally — measures such as “recall” and “precision” are especially important in such scenarios.
Clustering and extraction These tasks are exploratory in nature, performed using unsupervised methods, and evaluation is not as objective as it is for prediction and classification tasks.
Memory hook — why recall/precision matter

If every misclassification cost the same, accuracy would suffice. In topic assignment, calling a financial story “sports” may be far worse than the reverse — unequal error costs force you to look at precision (of what you flagged, how much was right) and recall (of what was truly there, how much you found) separately.

The closing comment on text mining: it, just like data-mining techniques, borrows heavily from statistical approaches, and the selection of learning methods depends on data preparation and on experience with text and data-science methods. The focus of the course is on the prediction aspects.

Careful reading

The slide says “just like data mining techniques, borrow heavily from statistical approaches” — text mining borrows from statistics; it is not itself described as a branch of statistics, and it is explicitly described as empirical rather than theoretical.

3.1 Whitespace, semicolons and blocks Exam alert

Key definition — significant whitespace

Python uses indentation (whitespace) to delimit code blocks instead of braces. A colon ends the header line and marks the start of an indented block.

  • The semicolon separates several statements placed on one line, e.g. a = 5; b = 6; c = 7.5. It does not terminate a statement the way it does in C or Java.
  • Whitespace is not merely visual alignment — it changes execution.
  • Whitespace is not what marks the end of a statement (that is the newline).
Distinguishing the three jobs

Newline ends a statement → colon opens a block → indentation delimits the block → semicolon lets you stack statements on one line. MCQs love to swap these four roles.

3.2 Objects, strong typing and None

Key definition — strong typing, no implicit conversion

Python is strongly typed and does NOT perform implicit conversion. Adding an int and a str raises TypeError. You must write a + int(b) explicitly.

a = 5
b = '9'
a + b          # TypeError: unsupported operand type(s) for +: 'int' and 'str'

Objects carry a type, and type(a) reports it. To test a type in a way that supports several possibilities at once, use isinstance with a tuple of types:

Key definition — isinstance with a tuple is an OR test

isinstance(a, (int, float)) returns True when a is an instance of either int or float. Passing a tuple of types returns True if the object matches ANY of them — it is an OR test, not an AND test. It is not an “instance of the tuple” test, and it does not attempt any conversion.

3.3 Assignment, aliasing and function side effects

Key definition — assignment copies the reference, not the data 
v1 = [1, 2, 3]
v2 = v1          # copies the REFERENCE, not the data
v1.append(4)
print(v2)        # [1, 2, 3, 4]  -- same object!

This is why passing a list into a function and mutating it inside the function is visible to the caller: append_element(v1, 5) modifies the parent list. The notebook uses this to demonstrate that Python has no value semantics for mutable containers by default.

Unpacking is the standard way to rebind several names at once, and the classic swap needs no temporary: c, b, a = a, b, c.

3.5 Strings, escapes and datetime

String literals and the r prefix

str10 = r'this\has\lots\of\backslashes'   # RAW string
Key definition — raw strings

The r prefix makes it a raw string: backslashes are taken literally, so escape sequences are NOT processed. Handy for Windows paths and regex patterns. It is not a byte string, it does not raise SyntaxError, and backslashes are not interpreted as escapes (that is the non-raw behaviour).

Ordinary escape sequences the notebook demonstrates: '12\34', '12\\34' (literal backslash), '12\n34' (newline), '12\b34' (backspace). Triple-quoted strings can span lines, and str3.count('\n') counts the newlines inside one.

Strings are immutable

str1.replace(',', '') returns a new string; the original is untouched. Same for upper(), lower(), strip(), and every regex substitution.

datetime arithmetic

Key definition — subtracting two datetimes

Subtracting two datetime objects yields a timedelta, which carries days, seconds and microseconds. Adding a timedelta to a datetime gives a datetime back.

Formatting uses strftime: dt.strftime('%m/%Y') on datetime(2019, 10, 29, 20, 30, 21) gives '10/2019' — %m is the two-digit month (10), %Y the four-digit year (2019).

3.6 Control flow

  • if / elif / else with and / or short-circuiting.
  • Chained comparisons. 1 < 2 > 3 < 4 means 1 < 2 and 2 > 3 and 3 < 4. Since 2 > 3 is False, the whole expression is False. It does not raise a SyntaxError, and it is not True.
  • for iterates over any iterable; continue skips the remainder of the current iteration; break exits the loop.
  • break only exits the innermost loop.
  • while loops on a condition. pass does nothing — it is a syntactic placeholder where a statement is required (e.g. a branch you intend to implement later). It is not continue (skip to next iteration), not break (exit the loop) and not raise.
  • range accepts start, end, step; the sequence includes the start point but EXCLUDES the endpoint, and the step may be negative. list(range(4, -4, -1)) counts down.
  • Ternary expression: 'negative action' if x < 0 else 'positive action'.
Key definition — the break trace (Set B Q1) 
seq = [0, 1, 2, 3, 4, 5, 5]
i = 0
for x in seq:
    if x > 4:
        break
    i += x

0+1+2+3+4 = 10, then x = 5 triggers break, so those two 5s are never added. i = 10.

The range mnemonic

“Start yes, end no, step can go backwards.” This is the same half-open convention as slicing — and it is exactly what makes range claim (ii) on the Set C Q3 list false.

04Module II — Data structures, functions & comprehensions

4.1 Tuples

  • Created by comma: tup = 1, 5, 9; or by conversion: tuple([1, 0, -1]), tuple('om omkar').
  • Ordered, immutable sequences. tup3 * 3 repeats; tup5 + tup4 concatenates.
  • tup4.count('m') counts occurrences.
Key definition — extended unpacking with * 
tup6 = 1, 2, 3, 4, 5, 6, 7
a, b, *rest = tup6       # a=1, b=2, rest=[3, 4, 5, 6, 7]

The starred target collects the REMAINING elements into a LIST — not a tuple. The same works from the right (*rest1, c, d = tup6) and in the middle (a, b, *rest2, c = tup6).

5.2 Indexing and slicing — views, not copies Exam alert

Key definition — the single most important NumPy fact for the exam

5.8 Pseudo-random numbers and random walks

Key definition — global seed vs isolated generator Exam alert

np.random.seed(12345) alters the GLOBAL random state.
np.random.RandomState(12345) creates an independent generator ISOLATED from that global state.

np.random.seed(12345)                    # affects np.random.* everywhere
rng = np.random.RandomState(12345)       # private stream; other code can't disturb it

The two objects have their own get_state(), and their first draws differ — np.random.randn(10) after the global seed gave 1.3316, 0.7153, ... while rng.randn(10) gave -0.2047, 0.4789, .... They are not aliases.

  • Pseudo-random numbers are generated by an algorithm with deterministic behaviour based on the seed of the random-number generator.
  • np.random.normal(size=(4,4)) draws from the standard normal distribution in one call.
  • Python's built-in random.normalvariate samples only one value at a time, so a 1000-value list needs a comprehension: [normalvariate(0, 1) for _ in range(1000)].
  • np.random.randint(0, 2, size=n) draws 0-or-1 with no loop required.
  • np.random.permutation(n) gives a random ordering of positions.
Key definition — the vectorised random walk (a beautiful exam example) 
nsteps  = 1000
draws   = np.random.randint(0, 2, size=nsteps)   # 0 or 1
steps1  = np.where(draws > 0, 1, -1)             # +1 / -1
walk1   = steps1.cumsum()                        # the whole trajectory

A random walk starting at 0 with steps of +1 and −1 occurring with equal probability. The loop-based Python version needs for i in range(nsteps); the NumPy version needs no loop at all — where maps 0/1 to −1/+1 and cumsum accumulates.

Key definition — first-crossing time via argmax

argmax returns the FIRST index of the maximum value in an array. In a Boolean array, True is the maximum value, so argmax on a Boolean expression returns the index of the first True. Hence the idiom for “first time the walk crosses level 10”:

(np.abs(walk1) >= 10).argmax()     # 67  -- first crossing
walk1[67]                          # -10 -- confirms it

Multiple walks scale the same code: np.random.randint(0, 2, size=(50, 1000)) gives 50 walks of 1000 steps; steps2.cumsum(1) accumulates along the second dimension. Then:

hits     = (np.abs(walks2) >= 30).any(1)          # which walks ever reach |30|
hits.sum()                                       # 31 of the 50
firsthits = (np.abs(walks2[hits]) >= 30).argmax(1)  # per-walk first hit
mct       = firsthits.min()                       # 131 -- minimum crossing time

6.1 Series

Key definition — Series

A Series is a one-dimensional array of values plus an explicit index — essentially a fixed-length dictionary mapping labels to values. It is not a two-dimensional table (that is a DataFrame), not an unordered set, and not a positional-only immutable sequence.

series1 = pd.Series([22, 33, 44, 55])
series1.index      # RangeIndex(start=0, stop=4, step=1)  -- default 0..n-1
series1.values     # array([22, 33, 44, 55])
  • Without an explicit index, pandas assigns the default integer index 0..n-1 — here 0 to 3, not 1 to 4, not None, and not the values themselves.
  • A custom index can be supplied: pd.Series(data, index=[...]).
  • Membership: 'c' in series2 tests the index labels.
  • Label access: series2['a']. Selecting several by list (series2[['c','a']]) returns them in the order you ask for, not index order.
  • Name attributes exist on both the Series and its index.
  • The index can be rebound: series1.index = [1, 2, 3, 4].
  • NumPy functions apply directly: np.exp(series2).

6.2 The alignment rule — pandas' defining feature Exam alert

Key definition — arithmetic aligns on LABELS, taking the UNION

When two Series with unmatched index labels are added, pandas aligns on labels and takes the UNION of the indices. Positions where either input has no value become NaN.

It does not drop the unmatched labels, it does not raise, and it does not take the intersection.

Key definition — the R-platform comparison

The notebook states explicitly that this automatic alignment of index labels and corresponding values is a feature comparable to the R platform. (The MCQ option is “The R platform” — not C, SQL or Java.)

The NaN-on-missing-label rule, demonstrated

PIN_code = {'Roorkee': 247667, 'Dehradun': 248001,
            'Haridwar': 249401, 'Nainital': 263001}
cities   = ['Dehradun', 'Haridwar', 'Nainital', 'Roorkee', 'Tehri Garhwal']
series4  = pd.Series(PIN_code, index=cities)
Key definition — labels present in the index but ABSENT from the dict get NaN

Tehri Garhwal is assigned NaN, because it is not present in the dictionary. Crucially, the extra label does NOT raise a KeyError, the dictionary order is not silently enforced, and the missing value is NaN, not 0.

Missing values are then detected with isnull() / notnull(), and the dict-based construction is exactly what the dict→Series conversion does in general: pd.Series(dict) maps keys to the index.

Broadcasting rules for DataFrame arithmetic
  • DataFrame − Series (a row): the Series is broadcast across the columns, and the subtraction is performed once for each row.
  • Broadcasting a raw ndarray: arr - arr[0] subtracts the first row from every row.
  • Direction matters: df4.div(2) is df/2 while df4.rdiv(2) is 2/df — the r prefix swaps the operands.
  • Unmatched labels between two DataFrames also produce a union with NaN; df4.add(df5, fill_value=0) substitutes 0 where one side is missing.

6.3 DataFrame construction

Key definition — building from a nested dict of dicts 
dict2 = {'Delhi':  {2011: 1.6, 2014: 1.9},
         'Mumbai': {2011: 1.9, 2012: 2.0, 2013: 2.1}}

The OUTER dictionary keys become the COLUMNS; the INNER keys are combined and SORTED to form the ROW index. So here the columns are Delhi and Mumbai, and the row labels are 2011, 2012, 2013, 2014 — with NaN where a city has no value for a year.

It is not the reverse (outer = rows), the inner keys are not discarded, and there is no MultiIndex concatenation.

  • A plain dict of equal-length lists/Series gives a DataFrame whose keys are columns.
  • .head(), .columns, .index inspect it; columns= and index= override the labels.
  • Column selection: df2['popcr']; attribute style df2.year also works.
  • Row selection by label: df2.loc[1].
  • Assigning a scalar fills the whole column: df2['area'] = 6000. Assigning an array (np.arange(6000, 6600, 100)) fills positionally. Assigning a Series with unmatched indices introduces NaN.
  • del df2['northern'] removes a column.

df.values returns the data as a 2-dimensional NumPy array when the columns have the same data type, and as an object array of a common dtype otherwise. It does not always return floats, it does not return a list of Series, and it does not return only the first column.

Key definition — the any(axis=1) outlier filter

Key definition — why filter(None, ...) appears

filter(None, iterable) drops all FALSY items — here the empty strings left behind when a token consisted entirely of punctuation. It does not remove alphabetic tokens, does not apply the substitution (the comprehension does that), and does not deduplicate.

Key definition — the negated character class

emma_f  = [re.sub(pattern5, r'', sentence.strip()) for sentence in emma_sents]

The ^ at the start of the class NEGATES it: the pattern matches every character that is NOT an alphabetic character, a digit or a space, so that such characters are removed. Everything else — letters, digits and spaces — is kept. It does not match the allowed characters, it is not an anchor-based whitespace trim, and it does not retain punctuation.

Key definition — the selective punctuation pattern Exam alert

emma_f1  = [re.sub(pattern6, r'', sentence.strip()) for sentence in emma_sents]

This pattern removes only the explicitly listed symbols, which deliberately RETAINS apostrophes and sentence periods. That is precisely why it is chosen instead of the aggressive negated class: with [^a-zA-Z0-9 ] you would destroy the apostrophes needed for contractions and the periods needed for sentence boundaries. The pattern is not about removing “all punctuation while retaining” these characters — it is the opposite: it removes these characters and retains the rest.

9.5 Expanding contractions

contraction_map = {"ain't": "is not", "can't": "cannot", ...}   # a large lookup dict

def expand_contractions(sent, mapping):
    pattern = re.compile('({})'.format('|'.join(mapping.keys())), flags=re.IGNORECASE|re.DOTALL)
    def replace(match):
        match        = match.group(0)
        if match.lower() in mapping:
            expansion = mapping[match.lower()]
            first_char = match[0]                   # <-- capture the case
            if first_char.isupper():
                return first_char + expansion[1:]
            return expansion
    return pattern.sub(replace, sent)
Key definition — why first_char is captured

In order to retain the correct CASE of the word, so that a capitalised contraction expands to a capitalised expansion. It is not about detecting whether the contraction begins with a letter, not about disambiguating repeated contractions, and not about stripping the apostrophe.

9.7 Stemming — Porter vs Lancaster Exam alert

Key definition — stemming itself

Stemming is the process of reducing inflected words to their base or root form, which is the REVERSE of inflection (inflection being the process of attaching affixes to create new word forms). It is not stopword removal, not affix attachment, and not POS labelling.

9.8 Lemmatisation and part-of-speech tagging

Key definition — lemmatisation vs stemming

WordNetLemmatizer returns a base form that is ALWAYS a real dictionary word (a lemma), because it consults WordNet. It takes a part-of-speech argument.

lemmatizer.lemmatize('bikes',   'n')   # 'bike'
lemmatizer.lemmatize('writing', 'v')   # 'write'
lemmatizer.lemmatize('spoken',  'v')   # 'speak'
lemmatizer.lemmatize('better',  'a')   # 'good'
lemmatizer.lemmatize('hotter',  'a')   # 'hot'

Note the last two: the lemmatiser maps comparative adjectives back to the positive form — better → good, hotter → hot. A stemmer cannot do this; that is the practical payoff of using WordNet.

Key definition — the canonical order

The pipeline runs: contraction expansion → lemmatisation → special-character removal → stopword removal. Learn this as a fixed sequence — it is asked as a “which is the correct order” question (Set C Q49).

Expand first, so can't becomes cannot and the pieces are real words. Key definition — what the term-document matrix holds

The term-document matrix produced by fit_transform contains the FREQUENCY with which each term of the vocabulary occurs in each document — raw term frequencies. It is not tf–idf weights (that needs TfidfTransformer), not first-occurrence positions, and not character counts.

min_df=1 sets the minimum document frequency; ngram_range=(1,1) restricts the vocabulary to unigrams.

Key definition — transform vs fit_transform on unseen data Exam alert

transform is used instead of fit_transform because the vocabulary has ALREADY been learned from the training corpus and must be REUSED, so that the feature dimensions correspond to those of the training data.

fit_transform on the unseen document would build a new, incompatible vocabulary and the classifier could not interpret the result. It is not about speed, not about a fit_transform restriction, and not about normalisation (that is the norm parameter).

Key definition — TfidfTransformer vs TfidfVectorizer

Input differs:
• TfidfTransformer takes the BAG-OF-WORDS FEATURES as its input — you must run CountVectorizer first.
• TfidfVectorizer takes the RAW DOCUMENTS as its input — it does counting plus weighting in one step.

TfidfTransformer(norm='l2', smooth_idf=True, use_idf=True)      # input = BoW matrix
TfidfVectorizer(min_df=1, norm='l2', smooth_idf=True,
                use_idf=True, ngram_range=(1,1))                 # input = raw docs

Both support ngram_range, so the “only unigrams” option is wrong; and TfidfTransformer can be applied to unseen documents as long as it is not re-fitted.

Python language

Whitespace delimits blocks; newline terminates a statement; semicolon puts several statements on one line; colon opens a block.

Strong typing: 5 + '9' → TypeError. isinstance(v,(int,float)) is an OR test.

None: sole instance of NoneType; the implicit return of a bare function; a common default argument; falsey but not a Boolean.

Mutable: list, dict, set, ndarray. Immutable: tuple, str, int, float. A tuple holding a list can still be mutated through that list.

a, b, *rest = seq → rest is always a list.

dict keys must be hashable — a list key raises TypeError.

enumerate yields (i, x); zip stops at the shortest input.

Lambda: one expression, implicit return, no __name__.

Generators drain: second list(g) is [], not an error.

File modes 'r' 'w' 'x' 'a' 'rb'. read(n) counts characters in text mode, bytes in binary mode.

NumPy

Slices are views, not copies. arr2d[:2, 1:] → [[2,3],[5,6]].

shape = (rows, cols); ndim = number of axes.

Fancy indexing a[[1,3,5],[0,2,3]] pairs the index lists element-wise, not rectangularly.

any() = OR, all() = AND; non-zero counts as True.

mean(axis=0) collapses rows → per-column. cumsum(axis=1) is row-wise.

arr.sort() sorts in place; np.sort(arr) returns a copy.

np.save = one array; np.savez = many arrays in one .npz.

np.random.seed is global; RandomState is isolated.

pandas

Series = fixed-length dict with labels; default index 0..n-1; missing labels → NaN.

Arithmetic aligns on the label union; NaN where a label exists on only one side.

DataFrame: a nested dict makes the outer keys the columns.

Index objects are immutable and set-like but can hold duplicates. A label lookup returns a scalar if unique, a Series if repeated.

loc = label (slice endpoint inclusive); iloc = position.

reindex is by label; take is by position; reindex(method='ffill') forward-fills.

drop returns a new object unless inplace=True.

rank() breaks ties by mean rank. idxmax() returns the index label.

Data preparation

read_csv: header=None → integer names from 0; skiprows takes row positions; chunksize → TextFileReader + get_chunk().

dropna: how='all', thresh=2 = at least 2 valid values. fillna(method='ffill', limit=2).

pd.cut is right-closed (60,100] and an integer count means equal width; qcut is equal frequency.

Outlier rule: (np.abs(df) > 3).any(axis=1) selects rows; winsorising replaces with np.sign(df)*3.

map(dict) adds a new column and preserves the original; replace() edits in place.

rename(inplace=True) returns None — assign the result instead.

index raises ValueError when absent; find returns -1.

.str methods skip NaN.

NLTK & text mining

Punkt = pre-trained sentence tokeniser; sent_tokenize is an instance of PunktSentenceTokenizer and generalises across languages.

TreebankWordTokenizer assumes sentences are already split and splits don't.

gaps=True → the pattern matches the separators, not the tokens.

Pipeline order: contraction expansion → lemmatisation → special-character removal → stopword removal.

Porter stems phase-wise (most popular); Lancaster applies rules iteratively.

Lemmatisation returns real dictionary words: better → good, hotter → hot.

CountVectorizer = raw frequencies (bag of words); TfidfTransformer takes a BoW, TfidfVectorizer takes raw documents.

transform reuses the fitted vocabulary; fit_transform learns a new one.

20 newsgroups ≈ 18,000 posts, 20 classes; SGDClassifier(loss='hinge') is an SVM.

The single most examinable definition. Text mining converts unstructured text into a numeric presence/absence matrix: rows are documents, columns are the unique words of the dictionary, and each cell holds 1 or 0. This matrix is sparse, all-positive, and missing values are a non-issue. Every technique in the course is then ordinary machine learning applied to that matrix.
